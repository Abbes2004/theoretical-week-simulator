# Decision 0004 — Local-host Hadoop environment inspection and benchmark dataset design

Status: Superseded in part by Decision 0005 (a real 3-VM Hadoop cluster
became available mid-session). Retained because it documents genuine
findings and still governs the parts Decision 0005 didn't change: the
`data/synthetic/benchmark_scale_2025_2026/` dataset design, the long-form
component-event representation, and the local-emulation fallback path
(still used automatically whenever the real cluster is unreachable).
Date: 2026-09-10.

## Windows host inspection (this machine, not the cluster)

Checked directly in this session:

```text
java -version   -> command not found
where hadoop    -> not found
wsl --list      -> only the internal "docker-desktop" distro (not a
                    general-purpose dev environment; left untouched)
```

Hardware: Intel Core i5-8265U, 4 cores / 8 threads, 7.88GB RAM (often
<1.5GB free), Windows 10 19045, Python 3.14.4, ~900GB free disk on D:.

**Conclusion at the time:** no real Hadoop execution was possible on the
Windows host itself. A `local-emulation` mode was built as the fallback:
the real `mapper.py`/`reducer.py` files run as local subprocesses, piped
through the external `sort` command (GNU coreutils, via Git for Windows)
in place of Hadoop's shuffle. This is NOT a distributed run -- no HDFS, no
YARN, no network shuffle, no JVM task-launch overhead -- and
`scripts/run_hadoop_job.py` labels every result it produces accordingly.

This mode remains the automatic fallback today (`--mode auto`) whenever
the real cluster (Decision 0005) is unreachable, and is still exercised by
the correctness-gate tests so the mapper/reducer logic is always validated
even without cluster access.

## Benchmark dataset design (`data/synthetic/benchmark_scale_2025_2026/`)

- Required scales generated by default: 100,000 / 500,000 / 1,000,000 POIs.
  Optional 5,000,000-POI ("XL") mode implemented but never generated unless
  `--scale 5000000 --confirm-large` is passed explicitly.
- Generated in bounded chunks (default 100,000 rows/chunk) using NumPy
  `SeedSequence` spawning for reproducible, independent per-chunk
  randomness -- chosen because this development machine has ~8GB RAM total
  and frequently <1.5GB free; a single 1M-row (let alone 5M-row) in-memory
  DataFrame construction was avoided by design, not just as an
  optimization.
- Dates drawn uniformly from `[2025-01-01, 2026-06-30]` (the mandated
  window), with a fixed 2% of each chunk forced into a guaranteed tie and
  1% forced onto the 2025-12-29/30/31 ISO year-boundary cluster (the only
  dates in this range where the calendar year differs from the ISO
  week-year -- see `src/ingestion/synthetic_benchmark_generator.py` for
  the `date.isocalendar()` verification), so these properties are
  guaranteed at every scale rather than left to chance.
- `canonical_reference/` is computed by the SAME vectorized engine used in
  Phase 1 (`src.optimization.vectorized_canonical.build_canonical_dataset_vectorized`)
  at generation time -- not a second, independently written "answer key".
- `component_events/` (long-form `Id_Sim, POI_Sim, component_name,
  availability_date, DATA_ORIGIN`, exactly 5 rows per POI) is a **synthetic
  computational benchmark representation invented for this evaluation**,
  not a confirmed company schema. It exists solely to give the Hadoop
  mapper something realistic to group/shuffle/reduce.
- `hadoop_input/` (flat TSV, one file per requested scale) is generated
  on demand by `scripts/prepare_hadoop_input.py`, never for every scale by
  default, per the instruction not to create large flat files unless
  needed for the scale actually being run.

## Correctness (local-emulation gate, before real-cluster access existed)

- 513-row demo dataset: 0 mismatches, exact match.
- 100,000-POI benchmark scale: caught and fixed a real bug (see
  `scripts/compare_hadoop_local.py::_normalize_blocking_element`) --
  `blocking_element` is a Python list in the demo canonical Parquet but a
  semicolon-joined string in the benchmark `canonical_reference` Parquet
  (flattened for CSV-friendliness at generation time); the comparison
  script's normalizer originally only handled the list case, silently
  treating every benchmark-scale blocking element as empty. Fixed and
  re-verified: 0 mismatches on 100,000 POIs.
- 1,000,000-POI benchmark scale: 0 mismatches, exact match (186.5s
  local-emulation wall clock for the full mapper→sort→reducer pipeline
  over 5,000,000 events).
